# SYNTHETIC remote-delay fixtures — not private data

Generated by `scripts/make_synthetic_remote_delay.py` (deterministic). Invented for testing ingestion and
analysis mechanics. Not derived from any real record, and not field evidence.

| File | Clock | Content |
| --- | --- | --- |
| `synthetic_ex1_console.csv` | `console_clock` | Probe RTT (ms) and loss (ratio) on `console->vehicle-router`; command transmissions |
| `synthetic_ex1_vehicle.jsonl` | `vehicle_controller_clock` | Command receipt, controller output, vehicle feedback, heartbeats (with a gap), controller restart, fault code |
| `synthetic_*_profile.json` | — | Import profiles: explicit column and signal maps; source names are deliberately not canonical names |

Built-in traps for honest analysis:
- The vehicle clock runs 0.8 s ahead of the console clock and the offset is **not declared**. Absolute latency from
  `command.sent` (console) to `command.received` (vehicle) must be reported as unavailable; only the change between
  in-window and out-of-window commands may be reported, stated as assuming a stable clock offset.
- The RTT probe measures `console->vehicle-router`, which is not proven to be the command path.
- The fault code `SYN-LINK-017` is invented.

Added for Engine v2: `synthetic_ex1_vehicle_io.csv` (10 Hz boom command input as received by the controller, and
boom rate) with `synthetic_vehicle_io_profile.json`. Healthy vehicle-side behaviour (delay 150 ms + 100 ms lag,
gain 0.4 deg/s per %) is unchanged during the network incident. The generator's `io_rows(slowdown_after=...)`
builds a vehicle-side slowdown variant used only in tests.

Added for the field-case demo (Engine v2.1):
- `synthetic_ex1_hydraulics.csv` + `synthetic_hydraulics_profile.json` (`vehicle_controller_clock`, 50 Hz, 09:03–09:10):
  boom cylinder pressure with three injected brief events — a one-sample spike 40 ms after a synthetic operator takeover
  at 09:06:58, a two-sample near-zero reading at 09:06:31.40, and a one-sample near-zero reading at 09:04:12.60.
  None of them is visible on a whole-recording plot; that is the point of the fixture.
- `synthetic_ex1_prior_console.csv` / `synthetic_ex1_prior_vehicle.jsonl`: the same network-delay pattern on EX1 in an
  earlier session (2026-02-18 14:00 UTC), used as a prior case on the same machine. Same profiles as the main session.

Added for the case memory test (`docs/CASE_MEMORY_TEST.md`): `synthetic_ex2_*` sessions on a second synthetic excavator,
EX2 (assets written as EX2, same profiles). `incident1` (2026-04-08): the same network-delay pattern as EX1.
`incident2_repeat` (2026-04-15): the same again. `incident2_changed` (2026-04-15): healthy link, and the boom's
vehicle-side delay rises from 150 to 450 ms between 09:06:00 and 09:07:30.
