# Investigation Engine V1 · local preview only

The browser uses the same-origin `/local-api` prefix with a fixed loopback upstream; this is enabled only in local runtime mode.

No Vercel/Render deployment, GitHub push, cloud purchase or external model request is part of this change. Existing production runtime is untouched. The executable API is disabled unless VEYRA_ENABLE_RUNTIME=true; the frontend selector is gated by NEXT_PUBLIC_ENABLE_RUNTIME=true.

## Run

Use Python 3.11+ and the existing Node/Next environment:

```sh
python -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements.txt
python scripts/fetch_cerberus.py
mkdir -p .local-runtime
VEYRA_ENABLE_RUNTIME=true VEYRA_AUTO_SEED=true DATABASE_URL=sqlite:///$(pwd)/.local-runtime/veyra.db PYTHONPATH=backend backend/.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8019
```

In a separate terminal:

```sh
cd frontend
WATCHPACK_POLLING=true NEXT_PUBLIC_ENABLE_RUNTIME=true NEXT_PUBLIC_API_URL=/local-api npx next dev --hostname 127.0.0.1 -p 3019
```

Open http://127.0.0.1:3019/product-demo . Existing Ask Veyra, grouped navigation, grid and side context are preserved. Choose CERBERUS or Industrial; legacy Fleet and Remote Support remain available.

Sources and SQLite live under ignored `work/cerberus` and `.local-runtime`. Normal restart preserves records; deleting these folders loses local data. The legacy global demo reset is disabled in runtime mode. Do not use this unauthenticated loopback prototype as a public service.

## CERBERUS demonstration

Enter an actor and create a local case. Load verified local CERBERUS files. Review the retrospective metre/frame assumptions and choose Run Investigation. The tool trace records source integrity, signal inspection, position error, candidate intervals and timestamp-gap checks. The reference is withheld in operational mode; reference-dependent measurements are unavailable there. No sensor cause is inferred from trajectory error.

Actual files: ANYmal 1 `1_compslam/{compslam_tum.csv,gt.csv}`, `2_compslam_post/{compslam_post_tum.csv,gt.csv}`. They contain 14,246/14,247 corresponding poses. Source frame for estimates is not assumed identical to DARPA reference; rigid registration is explicit. Default 300-second prefix yields online position RMSE about 0.472812 m and offline about 0.298184 m on this subset. These are retrospective trajectory residuals, not fault detection scores or evidence of a repair. The first 60 s is ill-conditioned; the geometry guard rejects it. Plots downsample to at most 800 points but metrics use all paired samples. Ground truth does not appear in operational query tools.

## Industrial demonstration

Choose Industrial, create a case with machine ID EX1. Either load an explicitly synthetic test or upload authorized CSV/JSON. The adapter requires explicit mapping for time/asset/signal/value/unit; optional version/event/scope are retained. Default supported columns:

```csv
timestamp,asset_id,signal,value,unit,scope,version,event_type
2026-01-01T14:02:00Z,EX1,rtt,40,ms,vehicle-router,v1,measurement
2026-01-01T14:06:00Z,EX1,rtt,470,ms,vehicle-router,v1,measurement
2026-01-01T14:06:00Z,EX1,packet_loss,18,%,vehicle-router,v1,measurement
```

Timestamp unit `iso8601` requires an explicit timezone; numeric units s/ms/us/ns are accepted by explicit mapping. RTT s/us converts to ms; loss ratio to percent. Unknown signals get statistics, not guessed anomaly semantics. RTT >200 ms and loss >5% are illustrative review thresholds, not OEM limits. Baselines need known matching system/model/environment and a named measurement scope; no comparison is forced when context is missing. Add new source data, then Run Investigation for an immutable new result. Numerical findings do not change merely because a user writes a narrative.

## Review and verification

Checks can be accepted/rejected/edited with actor/source/time. Only an accepted original allowlisted check can execute; edited or physical checks require manual review. Read-only checks either rerun stricter timestamp pairing or query the original anomaly-window rows. Decision records freeze the run ID/parameters/hashes/hypotheses. Actual actions require an explicit linked decision; outcomes require an explicit linked action. Simulated actions/results remain labelled. Verification is engineer-reported evidence, not telemetry attestation. A second named reviewer is recorded; local identities are not authenticated. Close requires an outcome, including an explicitly unverified one; reopening is supported.

Memory retrieval includes only other cases whose relevant feedback predates this case's creation, with matching known context and applicable outcome conditions. Unverified, simulated, mismatched and future records do not become eligible repair precedents. CERBERUS records are not a dataset of successful repairs. No model training or proven memory improvement is claimed.

## Current limitations

- Deterministic typed tool orchestration, not a general autonomous LLM investigator. no private data goes to an external model. A future model provider must be separately configured/authorized and constrained to the same tools; no provider secrets are logged.
- Local-only single-user preview, no production tenant ACL or authenticated approvals.
- No automatic physical actuation, remote patching, parameter writes or OEM reverse engineering.
- Source cap 5 MB/file, 50,000 rows/file, 12 sources/case and 40 runs/case; queries return at most 2,000 rows. No arbitrary code or filesystem paths are accepted. Original source content is treated only as data.

## Industrial support priority update

Industrial is now the default local path. Under Overview/Evidence/Changes, expand Machine context and record an attribute with effective time, source and confirmation. Missing or merely reported context is not silently confirmed. Remote access is a reported context value (`unknown`, `not_authorized`, `read_only_authorized`), never a software access grant. Run Investigation snapshots that version and uses only attributes applicable to the evidence time window.

In Next Checks, compare Reduce diagnostic uncertainty versus Restore operations. Run again after changing objective; ordinal rules explain priorities, availability, missing signals, resources and unknown cost/time. Accept/reject/edit requires a reason. New evidence or context requires a fresh run and check review. Only the local raw-source query is executable for industrial cases; other procedures remain manual. An observed manual check requires evidence IDs and actual time; inconclusive/not-performed statuses remain distinct.

Decision includes Dispatch readiness and an engineer preparation record. Outcomes includes source-linked support milestones; durations are reported or synthetic elapsed time, not measured time savings or verified recovery. Duplicate milestones produce unavailable durations until reviewed. Existing source/context versions and recorded reviews remain append-only. CERBERUS remains a technical validation option, not the commercial roadmap.

## Upload/analysis usability correction

Overview now shows a saved result summary first (peak values, units, measured scopes, source count and run ID). Initial flow is Upload CSV / JSON → Upload file → Analyze uploaded data. File selection supplies an editable local source reference; advanced mapping/metadata are collapsed. Successful analysis navigates from Evidence to Overview and focuses the actual saved result; errors are scrolled into view. Rerun settings collapse after results and prior runs are retained. Browser QA exercised actual file chooser upload and automatic result navigation. No backend calculations or original user records were altered by this UI fix.

## Simplified industrial workbench

The industrial workspace now has three primary actions: 上传日志 → 查看变化 → 选择下一步. Existing routes, Ask Veyra and field-case records remain. Desktop uses a compact dark navigation rail, quieter grid and instrument-style numbers; narrow windows use the full content width with an accessible page selector. Secondary fields, source hashes, context, previous runs and detailed computations remain disclosures. File selection, explicit upload and an always-visible 分析全部日志 button form the primary ingestion path.

The summary is calculated from exact run source IDs and verified hashes, grouped by signal/unit/measurement scope. It separates per-source early and later non-overlapping windows, retains historical peaks and never infers verified recovery. Different measurement paths and overlapping source windows are not presented as a valid sequential comparison. Historical run views use their original source set rather than later imports. Existing run payloads are preserved; the presentation is a derived view. A local `?case=case-…` link can open a specific industrial case without resetting its original records.

Validation: 63 backend tests, 9 connection tests, frontend build/type check, manual desktop and narrow viewport checks of the three main actions and the user's two already-imported example files. No production deployment or external model calls.

## Industrial import with a profile (M1, 2026-10-19)

Profiles make signal meaning explicit. A source column called `rtt` is never treated as network RTT unless the
profile's `signal_map` says so. See `backend/app/ingest/profile.py` for the full contract and
`fixtures/synthetic/remote_delay/` for two SYNTHETIC example profiles (console CSV, vehicle JSON Lines).

1. **Validate an export offline (no server, nothing stored or sent).** Standard library only:

   ```sh
   python3 scripts/validate_export.py path/to/export.csv path/to/profile.json --asset EX1
   python3 scripts/validate_export.py path/to/export.csv path/to/profile.json --asset EX1 --json --rows 20 > report.json
   ```

   Exit code 0 = accepted, 1 = needs review (some rows rejected), 2 = rejected or unsupported format, 3 = invalid profile.
   The report lists every rejected row with reasons, unmapped signals (kept for statistics only), clock and
   endpoint gaps, and reported context from the profile (never auto-confirmed).

2. **Import into a local case** (runtime enabled as above). Preview stores nothing; commit stores the original
   bytes immutably with the ingestion report. If rows were rejected, commit requires `review_reason`.

   ```sh
   CASE=case-…   # an industrial case; synthetic profiles only go into synthetic cases
   B64=$(base64 < fixtures/synthetic/remote_delay/synthetic_ex1_console.csv | tr -d '\n')
   PROFILE=$(cat fixtures/synthetic/remote_delay/synthetic_console_profile.json)
   BODY="{\"actor\":\"Engineer A\",\"filename\":\"synthetic_ex1_console.csv\",\"content_base64\":\"$B64\",\"profile\":$PROFILE,\"source_uri\":\"synthetic://remote_delay\"}"
   curl -s -X POST http://127.0.0.1:8019/runtime/cases/$CASE/imports/preview -H 'Content-Type: application/json' -d "$BODY"
   curl -s -X POST http://127.0.0.1:8019/runtime/cases/$CASE/imports -H 'Content-Type: application/json' -d "$BODY"
   ```

   Then choose Run Investigation in the workspace as before. Numeric measurements feed the existing analytics.
   Events, heartbeats, fault codes and command stages are stored with the source but are not yet analysed in
   runs (command-chain stage latency exists as a tested tool and is wired in M3). There is no import screen in the
   UI yet (M6).

3. **Regenerate the synthetic fixtures:** `python3 scripts/make_synthetic_remote_delay.py`.

Tests that need no web stack: `PYTHONPATH=backend python3 -m pytest backend/tests/test_ingest.py backend/tests/test_command_chain.py backend/tests/test_safety.py -q`.
The full suite now runs against a fresh temporary database per session (`backend/tests/conftest.py`) and refuses to start if the application is bound to any other database. The legacy demo reset refuses to drop tables while runtime case records exist.
